- 检索候选 SQL 同时要求 `org_id` 等值、可见会谈子查询、显式 `meeting_id`、发布指针匹配
- 音频 uuid 文件名经静态路径取 → 404
- 引用必须带 `recording_id` 且该录音属于被问会谈

## 2. ASR 质量(**单条录音,不构成任何率**)

- 样本:**1 条真实会议录音**,28.86s,3 个 10s 切片,立体声 24-bit/48kHz
- 模型:faster-whisper `small/int8`,词表 `zh-medproc-v1`,切片 3 次重跑
- 已观测到的识别错误(4 处,**经人工听判确认**,`demo/corpus/会议录音.校对说明.md`):
  `张公傅责→张工负责`、`布齐→补齐资料`、`没有报告→没有报价`、`北迅时间→保修时间`;
  另有 1 处数字错(`5月26日→5月20日`)与 1 处语义错(`不适用于外国人→不适用于Y300`)
- 稳定性:同音频三次转写有 1 处标点抖动 → **A/B 对比的基线固定为同一次运行的输出**
- **未测**:WER/CER(没有逐字对齐的完整金标转写,只有 6 处被确认的改动)、
  说话人分离、时间戳精度(时间一律按"切片范围",见 D-53)

| 环节 | 实测(单样本) | 口径 |

成本口径(D-42/D-52/D-58):
- 本地模型:`cost_basis=estimated` 且金额 0.00 —— **只表示外部 API 费用为零**,
  算力由 `duration_ms + device` 体现,不等于"免费";
- DeepSeek:无单价表 → `cost_basis=unknown`、金额 **NULL(不是 0)**;评测报告里体现为
  `unpriced_real_calls=15`,含义是"不知道花没花钱";机构一旦设预算即视为不可核算而**停止调用**;
- 本地行的 `tokens_in` 为 NULL(历史行仍是旧口径,汇总前须排除本地行)。

## 6. 单变量实验:阈值 0.66 → 0.64(结论:**不采用**)

**假设**(来自 D-59 的真实录音 5 题):短疑问句被 0.66 挡住,降到 0.64~0.65
可在**不引入无关候选**的前提下救回部分题目。

**做法**:只改阈值这一个变量(`--threshold 0.64`),同一扩充集、同一模型组合、
同一 rev;不改 `.env`,默认值未动,回滚即"什么都不用做"。

**结果(24 题,同一数据集 sha `73006ff2a45e`)**:

| 指标 | 0.66 | 0.64 |
|---|---|---|
| 证据命中 / 回答命中 | 0.857 / 0.786 | **0.857 / 0.786(完全相同)** |
| 漏判率 | 0.143 | 0.143 |
| 无答案正确拒答 / 误报 | 0.800 / 0.200 | 0.800 / 0.200 |
| 越权探针 | 10/10 | 10/10 |

**假设被自己的扩充集推翻**:没有任何一题由错变对,也没有一题由对变错;
变化只有"无关候选数变多"(4 题的过阈候选各 +1,含两道无答案题),
方向是**增加误答风险**而不是提升召回。

因此三条修正:
1. **作废**上一轮基于 5 题得出的"降到 0.64 可救回一题且无代价"的推断 ——
   它没有在更大样本上复现。这正是"单样本不外推"的代价,写在这里而不是悄悄删掉。
2. 阈值**不是当前有效的调节旋钮**:剩下的漏判一道卡在充分性线索规则(过阈候选 2 条
   仍判不足)、一道才是真正的召回问题;而两类误答(型号错配、日期归属)
   靠降阈值只会更多,不会更少。
3. 下一步的正确顺序:先修**实体/日期归属判定**(消误答),再看充分性规则是否过严;
   阈值调整必须等到有真实语料之后,并用独立留出集验证。

耗时与成本一并记录:两轮都是本地 bge-m3 + 真实 DeepSeek;
`cost_basis=unknown` 的真实调用 68 次(未定价 28 次),金额 NULL 而非 0(D-42)。
报告 `eval/reports_sample/devext_v3_t064.json`。

## 7. 留出集与污染声明

- 阈值 0.66 的标定**只用 dev 会谈**(D-48 纪律);本轮 项5 的分析用真实录音的 5 问,
  该录音**不在** `eval/dataset.json` 内 → test 集未参与任何调参决定。
- 若将来任何一次用 test 集结果决定过方案,必须在本节记录污染并另设独立留出集。
- **扩充集的性质必须说清**:它是**我在看到失败模式之后自己编写的**,因此只能当 dev 用,
  **不能当无偏留出集** —— 我用它得出"0.64 无收益"是可信的(同一数据上比较两个配置),
  但用它得出"系统检索质量 = 0.857"就是自证。真正的效果结论要等真实会谈录音扩到多场。
- 本轮未把任何新数据写入冻结的 `eval/dataset.json`(有测试断言:两份文件会谈/题目 id
  不重叠,扩充集不含 test split)。
- 当前 test 集只有 6 题,统计上不足以区分 0.66 与 0.64 的优劣 —— 扩充语料优先于调参。
