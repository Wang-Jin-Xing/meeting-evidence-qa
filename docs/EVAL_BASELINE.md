# 评测基线(五类分栏)

**这份文档的定位是"当前版本的基线",不是优化成果。**
每类都写清:测了什么、样本多少、口径怎么算、失败案例是什么。
所有数字都可从仓库里的工件或命令复算;没有测的写"未测",不估、不补。

## 1. 程序与权限测试(确定性,可重复)

| 项 | 值 | 口径 |
|---|---|---|
| `pytest -q` | **135 passed / 3 skipped** | 独立测试库(`TEST_DATABASE_URL`,会话独占锁) |
| 测试文件 | 20 个 `tests/test_*.py` | 含真实子进程 worker 的故障注入/接管 |
| 真 Provider 集成 | 显式 `MEET_TESTS_USE_REAL_PROVIDERS=1` 时 **3 passed** | 默认 skipped:避免每次全量测试加载 2.3GB 权重 |
| 权限探针 | 5/5 通过(mock 基线报告内) | 跨机构、restricted、发布指针、音频接口四路 |

覆盖的权限断言(节选,均在代码里可定位):
- 跨机构会谈/任务/音频/纪要/问答 → 404(与"不存在"同形)
- restricted:同机构未授权 404,白名单内 200
- 检索候选 SQL 同时要求 `org_id` 等值、可见会谈子查询、显式 `meeting_id`、发布指针匹配
- 音频 uuid 文件名经静态路径取 → 404
- 引用必须带 `recording_id` 且该录音属于被问会谈

## 2. ASR 质量(**单条录音,不构成任何率**)

- 样本:**1 条真实会议录音**,28.86s,3 个 10s 切片,立体声 24-bit/48kHz
- 模型:faster-whisper `small/int8`,词表 `zh-medproc-v1`,切片 3 次重跑
- 已观测到的识别错误(4 处,**经人工听判确认**,`demo/corpus/会议录音.校对说明.md`):
  `张公傅责→张工负责`、`布齐→补齐资料`、`没有报告→没有报价`、`北迅时间→保修时间`;
  另有 1 处数字错(`5月26日→5月20日`)与 1 处语义错(`不适用于外国人→不适用于Y300`)
- 稳定性:同音频三次转写有 1 处标点抖动 → **A/B 对比的基线固定为同一次运行的输出**
- **未测**:WER/CER(没有逐字对齐的完整金标转写,只有 6 处被确认的改动)、
  说话人分离、时间戳精度(时间一律按"切片范围",见 D-53)

| Y500 价格 | 0.7467 | 0.7768 | +0.0301 | 通过 |

## 4. 纪要与问答质量

**(a) 合成/虚构语料上的评测集**(`eval/dataset.json`,`eval-v2`,2 场会谈,dev 6 + test 6)
语料是**人工编写的虚构会谈转写文本**,不是真实录音 —— 它的分数只说明链路与评分脚本,
**不计入真实录音质量结论**。

| 组合 | 无答案题正确拒答 | 无答案误报 | 证据命中 | 回答命中 |
|---|---|---|---|---|
| mock LLM + mock 检索 | dev 0.5 / test 0.5 | 各 1 例 | 1.0 | 1.0 |
| DeepSeek LLM + mock 检索 | dev 1.0 / test 1.0 | 0 例 | dev 0.75 / test 1.0 | dev 0.75 / test 1.0 |

口径与已知局限(照实写):
- `answer_hit` 按金标线索**字面包含**判定 → 真实模型写"两年"而非"2年"记未命中(dev 0.75 的来源);
  **这就是"不止用关键词命中"的反例**,数字/型号/否定/证据支持需人工复核,已列在 D 系列决策;
- 真实 LLM 输出非严格确定(同输入两次跑纪要条目数 9 与 11 都出现过):跨次比较必须固定
  `prompt_version` 且看区间,不看单次;
- 结构合法性由 `minutes_validator.validate_minutes` 稳定保证(引用可解析、
  decision/todo 必须带证据、缺负责人/截止日期必须显式标待确认)。

**(b) 真实录音上的问答**:5 问中 3 问在 0.66 下有证据并给出正确回答(见 §3),
2 问证据不足。**样本 = 1 条录音 / 5 问,不外推。**

## 5. 耗时、用量与费用

| 环节 | 实测(单样本) | 口径 |
|---|---|---|
| 网页上传 → 索引完成 | 37.0s(受理到 index 落库) | 独立 worker 进程,含 3 次 ASR 调用 |
| ASR 单片 | 5.8s(首片,含加载)/ 1.7s、1.9s | `model_run.duration_ms` |
| bge-m3 建索引 | 24.7s/次 | 同上;`device=local:cpu` |
| bge-m3 查询 | 稳态约 0.1~3s;**冷加载 31.2s** | 首次问答含权重加载,不代表稳态 |
| DeepSeek 纪要/问答 | 1.6s / 约 1.0s | `device=remote:deepseek`,真 token 用量入台账 |

成本口径(D-42/D-52/D-58):
- 本地模型:`cost_basis=estimated` 且金额 0.00 —— **只表示外部 API 费用为零**,
  算力由 `duration_ms + device` 体现,不等于"免费";
- DeepSeek:无单价表 → `cost_basis=unknown`、金额 **NULL(不是 0)**;评测报告里体现为
  `unpriced_real_calls=15`,含义是"不知道花没花钱";机构一旦设预算即视为不可核算而**停止调用**;
- 本地行的 `tokens_in` 为 NULL(历史行仍是旧口径,汇总前须排除本地行)。

## 6. 单变量实验记录:阈值(项5)

**假设**:短疑问句在 0.66 下被判"证据不足",不是排序错也不是没召回
(阈值前 3 段全取到、金标段排第一),而是**阈值相对这类问句偏高**。

**只改一个变量**:阈值。方法是对 §3 已存的逐段相似度做算术重算,
**不重新调用任何模型、不改 `.env`、不改代码默认值**(默认 0.15 服务 mock,真实组合仍 0.66)。

| 阈值(B 链) | 可支撑回答的题数 | 混入的无关候选数 |
|---|---|---|
| 0.66(现状) | 3/5 | 1 |
| **0.65 / 0.64** | **4/5** | **1(未增加)** |
| 0.62 / 0.60 / 0.57 | 4/5 | 3 |
| **0.568**(= 第二问的最高相似度) | 5/5 | 3 |
| 0.55 / 0.50 | 5/5 | 4 / 5 |

读法:
1. 降到 **0.64~0.65** 能救回"保修时间确定了吗?"(0.6566),且**不引入新的无关候选**;
2. "什么时间之前要补齐?"要降到 **≤0.5681** 才被支撑,而那时无关候选已从 1 条涨到 3 条
   —— 再往下(0.55 是 4 条、0.50 是 5 条,即**每问都把不相关片段放进来**)
   就是拿**误答风险**换召回,不是免费收益(按纪律:降阈值单独不构成成功);
3. 第二问更可能的瓶颈不是阈值,而是"6 字短问句 vs 30 字长片段"的表示粒度
   → 指向下一阶段的候选策略(问句改写/短片段索引/轻量重排),而不是继续调阈值。

**结论与处置**:实验能力已具备(`eval/run_eval.py --threshold F`;相似度工件可复算)。
**正式配置不动**,因为:样本只有 5 问 1 录音、没有跨会谈金标,
0.64 这个点在此样本上"看起来更好"不足以宣布质量提升,也无从评估误答率。
回滚方式:默认值从未改变,`QA_EVIDENCE_THRESHOLD` 仍是唯一开关。

## 7. 留出集与污染声明

- 阈值 0.66 的标定**只用 dev 会谈**(D-48 纪律);本轮 项5 的分析用真实录音的 5 问,
  该录音**不在** `eval/dataset.json` 内 → test 集未参与任何调参决定。
- 若将来任何一次用 test 集结果决定过方案,必须在本节记录污染并另设独立留出集。
- 当前 test 集只有 6 题,统计上不足以区分 0.66 与 0.64 的优劣 —— 扩充语料优先于调参。
