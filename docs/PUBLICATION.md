# 公开版脱敏说明(PUBLICATION)

本仓库是**脱敏公开版**:代码、测试、评测框架、虚构语料与全部数值结论都完整保留,
唯一被移除的是"那条真实会议录音的文字内容"。这份文件写清楚移除了什么、为什么、
以及因此**不能**声称什么。

## 1. 为什么真实录音不入仓,转写文本也不入仓

录音原件(`会议录音.wav`,24-bit/48kHz/立体声/28.86s)从未提交,`storage/` 由
`.gitignore` 排除(`git ls-files storage/` 为 0)。但只藏住音频是不够的:
脚本会把 ASR 原始输出与人工校对稿写成 JSON/MD 工件,这些**文本本身就是那次会议的内容**
(谁负责哪台设备、报价金额、交付日期)。所以这些工件一并从公开版移除,并且是在
**全部历史提交**里移除(用 `git filter-repo` 重写,不是"最新提交里删掉"),
否则翻历史仍能取回。

| `demo/verification/real_audio_会议录音.json` | A/B 双链路完整报告(含文本) | 从历史删除,换成下面这份脱敏摘要 |
| 音频原件 | 28.86s 真实语音 | 从未提交 |

字符串级脱敏(全历史生效,针对仍然保留的文件):本地绝对路径里的 Windows 用户名、
作者实习过的公司名称、以及上面那些整句转录 —— 都替换成了占位文本。
文档里**保留**了 ASR 错字示例(如把"负责"识别成别的字这类对照),因为它们只是
"识别错了"的证据,不含任何会议业务事实。

## 3. 保留了什么(所以结论仍然可核)

- `demo/verification/real_audio_AB_summary.json` —— A/B 双链路对比的**全部数值**:
  逐题阈值前最高相似度与 Δ、命中切片、是否过阈、各阶段耗时、用量与成本口径。
  文本字段用占位替换,数值一位未改。
- `demo/verification/entry_acceptance_job6.json` —— 浏览器上传 → 任务落库 →
  **独立 worker** 领取的四阶段状态流转验收记录(其中的引用文本同样已占位)。
- `demo/verification/cold_start_acceptance.json`、`real_embedding.json` —— 冷启动与
  真实 Embedding 的留档。
- `eval/dataset.json`(冻结测试集)、`eval/dataset_dev_ext.json`(扩展 dev 集)与
  `docs/EVAL_BASELINE.md` 的五栏基线 —— 全部为**虚构语料**,不受脱敏影响。

## 4. 因此不能声称什么

- 不能声称"校对稿的逐处改动可被外部复核":金标听判记录只在作者本地完整版里。
- 不能把真实录音上的任何数字外推为"系统整体准确率":真实样本只有 1 条 28.86s、
  5 个问题,基线文档里已按单样本口径写明。
- 引用真实语料的相似度数值时,依据是 `real_audio_AB_summary.json` 的脱敏摘要,
  而不是原始报告文件。

## 5. 复现方式

脱敏不影响可复现:用**你自己的**录音跑 README「真实录音端到端」那一节的一条命令

```powershell
.\.venv\Scripts\python.exe demo/ingest_real_recording.py --audio <你的录音.wav> `
    --questions demo/questions_real_meeting.json
```

会在 `demo/corpus/` 与 `demo/verification/` 生成与上述摘要**同结构**的工件
(脚本运行时自行建目录,所以仓库里不留这些目录也不报错)。
