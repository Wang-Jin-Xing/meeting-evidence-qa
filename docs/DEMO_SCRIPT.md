# 3~5 分钟演示脚本

前置:`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dev_up.ps1`
(API + 独立 worker 起好,横幅与 `/meta` 都显示真实模型、阈值 0.66)。
浏览器准备两个账号:`demo_real_admin`(真实录音,由 `demo/ingest_real_recording.py` 建,
密码见 `demo/seed_demo.py` 默认值)、`demo_staff_c`(另一机构,用于越权对照)。

> 本仓库是脱敏公开版:**真实录音与其转写不在仓库里**(原因见 `docs/PUBLICATION.md`)。
> 下面 0:00–0:40 与"真实识别错误"相关的步骤,要作者自己拿原件录音重跑
> `demo/ingest_real_recording.py` 才复现;换任何人来讲这个项目,改用 `demo/seed_demo.py`
> 的虚构会谈走同一条链路即可(步骤见本文最后一节),链路、权限与状态机完全相同。

> 口径提醒:演示里不要说"准确率"。本仓库所有数字都是**单条录音、5 个问题**的实测,
> 不构成整体指标;讲清楚"哪些是识别错误、哪些是阈值挡住、哪些是未确认"比报一个百分比更有价值。

## 0:00–0:40 上传 → 持久化任务(强调 API 与 worker 分离)

1. 登录 `demo_real_admin`,新建会谈"演示·真实录音"。
2. 选择桌面上的 `会议录音.wav`(24-bit/48kHz/立体声,28.86s)→ 点「上传并开始处理」。
3. 界面提示 `已受理,任务 #N`,并显示 **上传只落盘与建任务;转写/纪要/索引由独立 worker 进程完成**。

一句话:"这一步 HTTP 请求就结束了,模型一个都没调 —— 任务是数据库里的行,
由另一个进程领取。所以服务重启、进程被杀,任务都还在。"

看点:任务卡从 `prepare → transcribe → minutes → index` 依次变绿(实测约 37 秒)。
可用 `docker exec mes-pg psql -U mes -d meeting_evidence -c "select id,status,current_stage,lease_epoch,locked_by from processing_job order by id desc limit 3"`
展示 `locked_by` 是 worker 进程自报的持有者、`lease_epoch` 是租约代次。

## 0:40–1:40 纪要:识别错误**原样保留**

打开该会谈,滚动到「3. 结构化纪要」。让听众看到这些**没有被修饰**的原文:

- `X200资料由张公傅责` —— 实际说的是"张工负责"
- `5月26日前,布齐…` —— 实际是"5月20日前,补齐资料"
- `Y300目前没有报告` —— 实际是"没有报价"
- `北迅时间未确定` —— 实际是"保修时间"

一句话:"转写是模型输出,我们不改它、不拿人工稿冒充它。每条都有对应的转写版本,
错在哪里一目了然 —— 这也是后面能做出校对对照实验的前提。"

同时指出右侧标签:`v1 · 自动转写 · 语音识别输出 faster-whisper:small@int8(可能含识别错误)`,
以及每条证据都带 `(精度:切片范围,非精确语句定位)` —— 时间来自 10 秒切片边界,不承诺精确到字。

## 1:40–2:30 引用回放:证据点得开、听得到那一段

1. 展开任一纪要条目的「证据 1 条」→ 显示 `SEG-xx [10s–20s]` + 片段原文 + 「▶ 播放本片段」。
2. 点播放 → 上方播放器只播该切片的 10 秒,**到 20 秒自动停**;说明栏显示
   `播放来源:derived_16bit_pcm (原件位宽 24…)`。
3. 顺带展示 DevTools Network:请求是 `GET /recordings/6/audio`,带 `Authorization`,
   响应 `206` + `Content-Range`。

一句话:"音频没有公开的静态目录,必须经鉴权接口;原件是 24-bit,浏览器普遍不放,
服务端**另存** 16-bit 副本播放,原文件一个字节没改,而且副本的帧数、采样率、声道
都跟原件校验过一致,否则切片时间就会错位。"

## 2:30–3:40 问答:命中与"证据不足"都如实

依次问三句(前两句有答案,第三句故意没有):

| 问句 | 预期界面 | 讲什么 |
|---|---|---|
| `Y500的价格是多少?` | 有回答 + 引用 + 相似度 ≈0.75 | 引用即证据:点开就是那 10 秒原文 |
| `保修时间确定了吗?` | **证据不足,系统未生成回答** | 校对后最高相似度 0.6566,阈值 0.66 —— 差 0.0034。系统不猜,也明确告诉你"原始检索 3 条、过阈值 0 条" |
| `今天主要谈了什么?` | 证据不足(候选 0) | 泛化问句在这种短切片语料上召回不稳,是下一阶段要解决的问题,不是"已经做好" |

一句话:"这个产品最难的不是让它答,而是让它**知道自己没证据**。我们分开统计
'原始检索数'和'过阈值候选数',就是为了把'没检索到'和'检索到但不够相关'区分开。"

## 3:40–4:30 人工确认与版本化(展示"不覆盖")

1. 「本版(v1)确认状态:未确认」→ 点「确认此版本」。
2. 再点「编辑为新版」:把 `张公傅责 → 张工负责`、负责人 `张公 → 张工`(改的是纪要条目,
   转写版本不动)→ 「另存为修订版」。
3. 展开「历史版本」:`v1 · ai_draft · confirmed · 确认人 #6` 与
   `v2 · human_edit · pending_review` **并排存在**。

一句话:"AI 的原始判断保留;人改的是新版本,谁确认的、什么时候确认的都记在版本上。
新版本必须重新确认——不然就等于替人背书他没看过的内容。另一个人如果基于旧版来改,
会被 409 拒绝,不会静默覆盖。"

## 4:30–5:00 越权对照(收尾必做)

换 `demo_staff_c`(另一机构)登录:会谈列表里**看不到**刚才那条;
直接把 URL 里的会谈 id 改成它也不行 —— 音频接口、纪要、问答全部 404,
界面不提供"选择机构"的入口。

一句话:"机构归属只从令牌里解析,列表和详情都是服务端按可见性过滤;
`restricted` 的会谈连同机构未授权的人都拿不到。"

## 现场故障预案

- **首次提问慢(约 30 秒)**:本地 bge-m3 冷加载。演示前先问一句预热。
- **worker 没领任务**:看 `.run/worker.err` 是否为空、`scripts/dev_up.ps1` 是否把两侧都拉起;
  `processing_job` 里 `lease_expires_at` 过期后会被重新领取(租约 600s)。
- **DeepSeek 不可达(断网)**:纪要/问答会显示失败或结果未知,**不会**回退成 mock ——
  这本身也是要展示的行为,不要现场粉饰。
- 想省事:直接用仓库里已有的会谈 #6(已跑完全链路、有 v1 已确认 + v2 待确认),
  跳过第 0 节上传,其余照讲。
